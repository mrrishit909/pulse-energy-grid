# Data contracts

Grain, keys, units and rules. Enforced in `tests/` (pytest). JSON Schemas (draft 2020-12) are generated by `pipelines/contracts.py`
into `data/contracts/*.schema.json`, one per published artifact, and every artifact is validated against its schema.

## Interim tables (not published)
### `data/interim/eia_long.parquet` (ingestion output, raw as published)
| Field | Type | Semantics |
|---|---|---|
| ba | str | `CISO` or `ERCO` |
| kind | str | `D` demand, `DF` EIA day-ahead forecast, `NG` total net generation, `TI` total interchange, `GEN` net generation by fuel |
| fuel | str | fuel code for `GEN` (NG, COL, NUC, OIL, OTH, SUN, WAT, WND), else empty |
| ts_utc | timestamp (naive, **UTC**) | **start of the interval**. EIA-930 stamps are hour-ending (value stamped T covers [T-1h, T]); ingestion subtracts 1 h so ts_utc is hour-beginning everywhere downstream. Evidence: see Timestamp convention below |
| value | float, nullable | MWh in the hour (= average MW). Unit as published; no rescaling |

### `data/interim/hourly.parquet` (cleaned, one row per BA x UTC hour on the full grid)
Wide table: `ba, ts_utc, demand, demand_forecast, net_gen, interchange, gen_{fuel}...` plus for each series a flag column
(`ok`, `null`, `missing`, `flagged`, `imputed`). Rows exist for **every** UTC hour of the window (40,776 per BA); missing source rows are NULL with flag `missing`.
`temp_c`, `dew_c` (population-weighted BA values) and `local_ts`, `local_date`, `local_hour`, `local_dow` are added.

## Cleaning rules (applied in this order, each counted in the ledger)
1. **Grid**: expected slots = every UTC hour from 2021-01-01T00 to 2025-08-26T23. Slots absent from the source are `missing_slots`.
2. **Null**: source value null -> `null_value`.
3. **Range**: demand, net generation must be > 0 and demand within [0.2, 2.0] x the series median; else flagged `flagged_outlier` (rule `range`).
4. **Spike (hampel-style)**: for demand, forecast and net generation, a value is flagged when it differs from the median of the same local hour-of-week across the
   surrounding +/- 3 weeks by more than 35 percent *and* differs from both neighbours (previous and next hour) by more than 20 percent in the same direction (rule `spike`).
5. **Short-gap imputation**: runs of at most 3 consecutive null / missing / flagged hours in demand, forecast, net generation and temperature are filled by linear interpolation and flagged `imputed`. Imputed demand hours are available as lag inputs but are **excluded from forecast targets and metrics**. Longer runs stay NULL.
6. Flagged values are **never silently dropped**: they are retained in interim with a flag, counted in `reconciliation.json` and `quality.json`, and excluded from aggregates and modelling targets.

Invariants (tested exactly): per series `grid_slots = raw_rows + missing_slots` and `raw_rows = kept + null_value + flagged_outlier`.
Fuel series (`GEN`) are checked for nulls and extreme spikes but negative values are physical (e.g. station service, storage charging reported in OTH) and are kept.

## Published artifacts: `site/public/data/` (schema version `v1`, each under 400 KB gzip)
| Artifact | Grain | Key | Contents |
|---|---|---|---|
| `meta.json` | n/a | n/a | window, split dates, BAs, stations, attribution, per-artifact tags and byte sizes |
| `facts.json` | BA | BA | every headline number used in site copy (single source of truth) |
| `reconciliation.json` | BA x series | (ba, kind, fuel) | source ledger (grid slots, raw rows, kept, excluded by reason), fuel-sum vs total, demand + interchange balance, weather coverage |
| `quality.json` | BA | BA | gap runs, DST day counts and transitions, outlier rules with counts, example spikes |
| `demand_profile.json` | BA x date, month x hour, hour of week | local time | daily mean/peak/min demand and temperature, mean demand by (month, local hour) and by local hour-of-week, annual stats |
| `fuel_mix.json` | BA x fuel | fuel | annual share, mean MW by (month, local hour) per fuel, capacity proxies, evening ramp statistics |
| `weather_relation.json` | BA x hour | local hour | per-hour cooling/heating degree-coefficients, temperature bins of demand, percent change per deg C |
| `forecast_eval.json` | BA x model | model id | MAE, MAPE, RMSE, bias, peak-hour MAPE, by-hour and by-month MAPE; interval coverage raw and conformal; paired comparison vs EIA with bootstrap CI; permutation importance |
| `forecast_samples.json` | BA x test week | label | hourly actual, EIA, seasonal-naive, GBM P50/P10/P90 for 3 labelled weeks; daily test errors |
| `dispatch_model.json` | BA x class, day | id | generator classes, battery, assumptions (SIMULATED), reference days (observed demand/renewables), scenarios, formulation, reference LP text |
| `dispatch_results.json` | BA x day x scenario | (ba, day, scenario) | optimal dispatch, battery SoC, curtailment, unserved, shadow price per hour, cost breakdown, CO2 |
| `dispatch_test_vectors.json` | vector | n/a | inputs and expected outputs for the browser HiGHS parity test |
| `grid_topology.json` | bus / branch | id | pglib IEEE 14-bus case, labelled illustrative |

Units: demand and generation MW (hourly average; MWh per hour); temperature degC; costs USD; prices USD/MWh; CO2 tonnes; battery energy MWh; SoC arrays have 25 entries (hour 0 start through hour 24 end).
Time: all stored timestamps are UTC unless the field is named `*_local` or the artifact says local. Local conversions use the IANA zones `America/Los_Angeles` (CISO) and `America/Chicago` (ERCO). The CISO footprint spans a single time zone; ERCOT is in Central Time (a small part is in Mountain Time, ignored).
Index conventions: `month_hour_mean_mw[(month-1)*24 + local_hour]`, `how_mean_mw[dow*24 + local_hour]` with dow 0 = Monday.

## Honesty tags
Every artifact has `tags`: field group -> OBSERVED | DERIVED | PREDICTED | SIMULATED | SYNTHETIC (combinations joined by `/`).
Examples: demand series OBSERVED; capacity proxy DERIVED; forecasts PREDICTED; dispatch results and all cost, heat-rate, ramp, battery assumptions SIMULATED.
`gbm_perfect_weather` is PREDICTED and carries `available_at_forecast_time: false` (it uses observed target-hour temperature as a stand-in for a perfect weather forecast and is an upper bound, not a deployable model).

## Reproducibility
`uv run python -m pipelines.run_all` rebuilds everything from `data/raw`. Outputs are byte-identical across runs (sorted keys, fixed seeds, `generated_at` = latest raw retrieval time from the manifest).
Raw files are gitignored and re-creatable (`--fetch`); checksums in `data/manifests/`.

## Refinements from phases 05-13 and the design data requests DR-1..DR-11 (verified against the built artifacts)

**Layout.** Per-BA content is under `bas.{CISO,ERCO}`. Tags: demand/generation OBSERVED(/DERIVED), forecasts PREDICTED, dispatch and every cost/ramp/battery assumption SIMULATED. `grid_topology` is tagged **SYNTHETIC** (DR-10): the pglib file is real published data, but of a hypothetical 1962 test network, not an observation of any grid; it also carries `tag: "SYNTHETIC"` and `illustrative: true`, and the UI shows the tag plus `ILLUSTRATIVE`.

**Forecast.** `forecast_eval.bas[ba].models` has six ids: `seasonal_naive`, `eia_day_ahead`, `eia_debiased` (EIA x trailing 28-day actual/forecast ratio, DERIVED), `gbm`, `gbm_stacked` (corrects the EIA forecast; uses it as input), `gbm_perfect_weather` (not deployable). `comparisons[]` are paired daily comparisons with a circular block-bootstrap 95% CI; `comparison_vs_eia` is the headline (`gbm` vs `eia_day_ahead`) and `best_model` is the lowest-MAPE deployable model. Deployed models are refit on train+validation; intervals are conformalised with the offset computed on validation residuals of the train-only model.
- **DR-8.** `forecast_samples.bas[ba]` has `best_model` and `cqr_offset_mw`; each week has raw `gbm_p10_mw`/`gbm_p90_mw`, calibrated `gbm_p10_cqr_mw`/`gbm_p90_cqr_mw` (raw minus/plus the offset) and `best_mw` (the median forecast of `best_model`, which may be `gbm`, `gbm_stacked` or `eia_debiased`).

**Dispatch days (DR-1, DR-2).** `dispatch_model.bas[ba].days[]` are local hours 0..23 in the BA's IANA zone. Days with 23 or 25 hours are never selected, so `dst_transition` is always `false` (the field is published so the client need not assume it). Each day carries `observed_gen_mw` = {EIA fuel code: [24]} (OBSERVED, signed as published, so CISO `OTH` can be negative) and `observed_interchange_mw` [24] (OBSERVED, EIA sign: positive = export). `net_imports_mw` = minus the interchange. The identity sum(observed fuels) - interchange = demand holds only to EIA's own residuals (see reconciliation.json). CISO has a fifth day with `intro: true` (id `intro`), chosen by a published rule (`intro_rule`): the complete local day with the highest share of demand met by solar in the latest year with at least 8000 clean demand hours (2024); ERCO has none. Seasonal days: the complete weekday of the test year whose daily peak is closest to the q-quantile of that season's weekday peaks (q = 0.5, 0.5, 0.9 for summer, 0.5).

**Series and signs (DR-5).** `classes[].group` in {solar, wind, nuclear, hydro, gas_cc, gas_ct, coal, oil, imports, other}. `display_order` lists ids centre outward: `solar, wind, imports, other, hydro, nuclear, battery_discharge`, then the remaining dispatchable classes by `marginal_cost_usd_mwh`. `fixed_series` documents `imports` and `other`; `sinks` = `battery_charge`, `curtailment`, `exports`. **Sign convention:** sources positive, sinks negative when drawn; every array in `dispatch_results` is a non-negative magnitude; only `net_imports_mw` is signed (positive import = source `imports`, negative = export = sink `exports`); `fixed_other_mw` is clamped at 0 and is never a sink.

**Controls (DR-6).** `dispatch_model.bas[ba].controls[]` = {id, label, unit, kind, min, max, step, default, param_path} (enum controls have `options` instead of min/max). They live per BA, not at the top level, because the battery power range depends on the BA. Ids are exactly the keys of every `params` object: `renewables_scale`, `demand_growth_pct`, `heat_wave_c`, `battery_power_mw`, `battery_hours`, `outage_class` (`none` or a dispatchable class id), `outage_pct` (an eighth control not in the request, needed to express the 35% outage preset). `bas[ba].scenarios[]` expresses all six presets as plain control values (absolute battery MW), and the top-level `scenarios[]` has only id, label and description. Extremes of every control, all corners and 10 seeded random points per BA solve to optimality (tested).

**Results (DR-4).** `dispatch_mw` keys = dispatchable class ids + `battery_discharge`; `cost_breakdown_usd` keys = class ids + `battery_wear` + `unserved_voll`, summing to `objective_usd` (tested, 1e-6 relative); the schema types both. `marginal_class[24]` (class id, `unserved` or `surplus`) is computed in Python by the rule in `analytics/dispatch.py::marginal_class` (a class strictly inside its bounds with the highest marginal cost; `unserved` when load is shed; `surplus` when anything is curtailed and nothing is interior). It is descriptive, not a dual, and is informative in parity checks. `price_usd_mwh` sign and unit (DR-11): the row dual of the hourly balance constraint = d(objective)/d(demand in that hour) in USD per MWh, positive when extra demand costs more, equal to VOLL (1000) when load is shed, about 0 when curtailing.

**Test vectors (DR-7).** Every BA x every reference day (5 for CISO, 4 for ERCO) has 6 presets, 4 seeded random interior control combinations, one `stress_unserved` and one `stress_curtailment` case, 108 vectors in total. Each has `params` (all 7 control ids), `expected` (objective, cost breakdown, unserved, curtailed, SoC, `price_usd_mwh`, `price_comparable`, CO2, `marginal_class`) and `lp_text_sha256`. Pass criteria: objective within `tolerance_rel` 1e-6, cost breakdown, unserved and CO2 within tolerance; prices compared (`tolerance_price_usd_mwh` 0.01) only when `price_comparable` is true, because duals are not unique at degenerate vertices (`price_comparable` was verified by forward/backward finite differences in Python). **LP text export:** the text itself (about 30 KB each) is not stored per vector; the exact generator inputs are (ba, day, params with `dispatch_model.json`), plus one full reference text (`reference_lp`). The text format is fixed: CPLEX LP, numbers as C `%.10g`, variables `x0..`, rows `r0..`, bounds as `lb <= xj <= ub` with `+inf`, objective terms for nonzero costs only. A JavaScript port must reproduce `%.10g` exactly (including exponent formatting) for the hash to match; if it cannot, the hash is a diagnostic and objective parity is the criterion. All published inputs are rounded to 4 decimals before any LP is built, so the browser and Python use identical numbers.

**Facts (DR-9).** `facts.bas[ba]` adds `interchange_abs_mean_pct_of_demand`, `interchange_net_mean_pct_of_demand`, `deepest_bite_month` (calendar month with the lowest mean midday 10:00-15:59 net load in `bite_year`), `deepest_bite_month_mean_midday_net_load_mw`, `midday_net_load_min_mw_first_year` and `_latest_year` (for both BAs, with the years in `net_load_first_year`/`net_load_latest_year`), and `facts.global.definitions` defines each.

**Per-year profiles (DR-3).** `fuel_mix.bas[ba].month_hour_mean_mw_by_year` = {year: {demand, SUN, WND: [288], months_present}} for local years 2021..2025, same index as `month_hour_mean_mw`, `null` where a (month, hour) has no clean data (2025 is partial: to 2025-08-26, so `months_present` = 8).

**Solver versions (DR-11).** `dispatch_model.solver_versions` records the Python highspy and HiGHS versions used to produce every number. The browser is declared as highs@1.15.3 (HiGHS-wasm) by the web build; that build is not run here, so cross-version agreement (including duals) is untested by this repository and the vectors define what must agree.

**Not supportable as asked.** None of DR-1..DR-11 was declined. Deviations: controls are per BA (above); an `outage_pct` control was added; `dispatch_mw` has no entry for exports or curtailment (those are separate arrays).

## Timestamp convention (fix P04-DATA-003)
EBA.txt hourly stamps (`YYYYMMDDTHH`, UTC) are **hour-ending**. The first build treated them as hour-beginning, which pushed every local hour one hour late (observed solar after sunset). Evidence from the data itself: mean solar by stamp hour is ~0 for the stamp that ends at/before sunrise, and after shifting the stamp back one hour (interval start) the month-by-month solar centroid is within +/-0.45 h of astronomical solar noon (CISO ~12:50 PDT, ERCO ~13:30 CDT in summer) versus +1.1 to +1.3 h before; correlation of hourly solar with a clear-sky elevation curve peaks when the interval midpoint is used (CISO 0.917 at offset 0 vs 0.865 at +1 h). EIA documentation of the convention: UNVERIFIED (the EIA Grid Monitor and API documentation pages returned no retrievable text on this machine). Weather: NOAA observations are instants rounded to the nearest UTC hour and are aligned with the interval start of the same label (an at-most 30 minute mismatch with hourly-average demand, documented, not corrected). `local_hour`, `local_date` and all `[24]` arrays refer to the interval start in the BA's zone (hour 13 = 13:00 to 14:00 local); the window is 2021-01-01T00 to 2025-08-26T23 interval starts.

## Per-series timing correction (P04-DATA-004)
`data/interim/eia_aligned.parquet` (ba, kind, fuel, stamp_utc, ts_utc, value, c_hours, timing_excluded, timing_reason) is the cleaned input. `stamp_utc` is the raw EIA stamp; `ts_utc` is interval start after the correction; `c_hours` is the shift applied to that row beyond the hour-ending conversion. `data/manifests/timing_corrections.json` and `quality.json.timing` (tag DERIVED) list, per BA, the change dates and per period the shifts for generation (`c_gen_h`: net generation and all fuels), demand (`c_D_h`), interchange (`c_TI_h`) and the day-ahead forecast (`c_DF_h`), with the evidence (solar offset before/after, identity residual before/after, forecast MAPE before/after). Ledger invariant is now `raw_rows = kept + null_value + flagged_outlier + timing_excluded`; `status` gains the value `timing` for excluded hours. The extraction is padded by 3 h so shifts can cross the window edge. `fuel_mix.annual_share_by_year` no longer has a 2020 entry (D-031).
