# Methodology

Generated by `pipelines/methodology.py` from the published artifacts (do not edit by hand). Every number below is the number in `site/public/data/`.

## Window and split
UTC hours 2021-01-01T00:00:00 to 2025-08-26T23:00:00 (40,776 hourly slots per balancing authority). Train 2021-01-01T00:00:00 to 2023-06-30T23:00:00; validation to 2024-08-31T23:00:00; test after that. Split is by the UTC time of the forecast target hour. Hyper-parameters are chosen on validation (train-only fit); the deployed models are refit on train plus validation; the test period is never used for any choice.

## Ingestion and cleaning
EBA.zip is streamed once (`pipelines/ingestion/eia.py`); NOAA ISD station files are reduced to one observation per station-hour (`pipelines/ingestion/noaa.py`). `pipelines/cleaning/clean.py` builds the full UTC grid, flags null / range / spike values, linearly fills runs of at most 3 hours (flagged `imputed`, never used as targets) and builds the population-weighted BA temperature. Local time uses IANA zones, so DST days have 23 or 25 hours (see `quality.json`).

## Forecasting
Forecast origin is local midnight starting the target day. Models: seasonal naive (same hour last week), the EIA day-ahead forecast, EIA debiased with the trailing 28-day actual/forecast ratio, and quantile gradient boosting (scikit-learn `HistGradientBoostingRegressor`, LightGBM unavailable on this machine; see DATA_SOURCES.md) in three variants. Target is demand divided by a level (trailing 7-day mean, or the EIA forecast for the stacked variant). P10/P50/P90 are separate quantile fits; an 80% interval is conformalised with the CQR offset computed on validation.

### Drift of the EIA day-ahead forecast

Bias = 100 x mean(EIA-930 day-ahead demand forecast - demand) / mean(demand) per local calendar year, over hours where both are clean (years with at least 1000 such hours; negative = the BA's own forecast ran low). It is `facts.bas[ba].eia_dayahead_bias_pct_by_year`; `facts.eia_ciso_dayahead_bias_pct` = -6.35% is the CISO value in 2025 (partial year). Part of the GBM's margin over the EIA forecast in CISO is this drift in the published series, which is why `eia_debiased` is reported beside it.

## Dispatch LP
Single-node 24-hour least-cost dispatch. Minimise fuel/VOM cost + battery wear + value-of-lost-load penalty subject to hourly energy balance, battery state of charge, hydro daily energy, ramp limits and capacity bounds.

- g[c,t] dispatchable class output MW (c in dispatchable classes, t = 0..23)
- curtS[t], curtW[t] curtailed solar and wind MW (used = availability*renewables_scale - curtailment)
- ch[t], dis[t] battery charge and discharge MW
- soc[t] battery energy MWh at the END of hour t (t = 0..23; the start-of-day SoC is the constant soc0)
- uns[t] unserved energy MW
- balance[t]: sum_c g[c,t] - curtS[t] - curtW[t] + dis[t] - ch[t] + uns[t] = Dnet[t] - Savail[t] - Wavail[t]; Dnet = demand*demand_scale + heat_shock - imports - fixed_other
- soc[t] - soc[t-1] - eta*ch[t] + dis[t]/eta = 0 with soc[-1] = soc0*E, eta = sqrt(round_trip_eff)
- sum_t g[hydro,t] <= hydro_energy_mwh
- ramp: |g[c,t] - g[c,t-1]| <= ramp_frac*capacity for t = 1..23 (two rows each)
- bounds: min(pmin*cap, cap*a) <= g <= cap*a (a = 1 - outage_pct/100 for the outaged class, else 1), 0 <= curt <= availability, 0 <= ch,dis <= battery_power_mw, soc_min*E <= soc <= E with E = battery_power_mw * battery_hours, soc[23] >= soc0*E, uns >= 0

All cost, ramp, battery and fuel-price parameters are assumptions (SIMULATED) listed in `dispatch_model.json`; capacities are the maximum observed hourly generation of each fuel. Reported cost = HiGHS objective; the per-class breakdown sums to it (tested).
